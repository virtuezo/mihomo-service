# Mihomo Service

Служба Windows, которая держит запущенным ядро [mihomo](https://github.com/MetaCubeX/mihomo) в режиме **TUN**
и пускает весь трафик машины через **fallback**-группу ваших прокси. Системный прокси и настройка приложений
не нужны: трафик перехватывает TUN-адаптер. Без туннеля интернета нет — это обеспечивает **kill-switch** на
Windows Filtering Platform.

Прокси-серверы служба не предоставляет: нужны свои (vless, vmess, trojan, ss, socks5, hysteria2, tuic,
wireguard — всё, что поддерживает mihomo).

## Возможности

- **Весь трафик через туннель** — TUN с `auto-route`, DNS через туннель (fake-ip, DoH), IPv6 выключен.
- **Fallback-группа** из `proxies` (и подписок `proxy-providers`) в порядке объявления: трафик идёт через
  первый живой прокси, при его отказе — через следующий.
- **Kill-switch** — постоянные WFP-фильтры: действуют с ранней загрузки Windows, при остановленной или упавшей
  службе; в сеть выходит только ядро и туннель (локальные сети — по выбору). UDP, который ушёл бы мимо прокси
  без поддержки UDP, блокируется.
- **Надёжность** — ожидание сети при загрузке, перезапуск упавшего ядра, перезапуск службы через SCM;
  `config.yaml` проверяется `mihomo -t` до применения, изменения подхватываются на лету.
- **Обновление** службы и ядра с GitHub одной командой — с проверкой SHA-256 и откатом при сбое.
- **Диагностика** — отчёт о маршрутах, DNS, внешнем IP по TCP и UDP; секреты в копиях конфига скрыты.
- **Регион Windows** — скрипт выставляет страну и часовой пояс всем пользователям (для приложений, которые
  проверяют не только IP).

## Требования

- Windows 10/11 или Windows Server 2019+ (x64), права администратора. Проверено на Windows 11 и Windows Server 2025.
- Процессор с AVX2 для ядра из релиза (сборка `amd64-v3`: большинство CPU с 2013–2015 годов, но не все
  Pentium/Celeron); для остальных — см. шаг 3 ниже.
- Свои прокси-серверы.

Проект в версии 0.x и не связан с авторами mihomo.

## Быстрый старт

1. Скачайте `MihomoService-v<версия>.zip` со страницы [Releases](https://github.com/virtuezo/mihomo-service/releases/latest).
   Снимите с архива пометку «из интернета» (иначе Windows спрашивает подтверждение на каждый скрипт):

   ```bash
   powershell Unblock-File MihomoService-v0.2.1.zip
   ```

   Распакуйте, например, в `C:\Program Files\MihomoService`.

2. Положите рядом с `MihomoService.exe` свой `config.yaml` со списком `proxies` — первый сервер основной,
   остальные резервные (пример — в разделе [config.yaml](#configyaml)). Остальное служба настроит сама.

3. Проверьте конфиг — сборку, `mihomo -t`, сеть:

   ```bash
   MihomoService.exe check
   ```

   Если ядро не запускается (процессор без AVX2), поставьте совместимую сборку ядра (`update.cmd` описан ниже)
   и повторите проверку:

   ```bash
   update.cmd -SkipService -CoreBuild amd64-compatible -Force
   ```

4. Установите службу (права администратора скрипт запросит сам):

   ```bash
   install-service.cmd
   ```

   Служба запускается сразу и потом при каждой загрузке. Kill-switch включается при установке: интернет есть
   только через прокси. Выключить — `killswitch.cmd off`.

5. Убедитесь, что трафик идёт через прокси: `diag.cmd` собирает отчёт в `logs\diag-<время>\report.txt`
   (внешний IP по TCP и по UDP, маршруты, DNS). Журналы — `logs\service.log` и `logs\mihomo.log`.

Обновление — `update.cmd`. Удаление — `uninstall-service.cmd`; **запустите его до удаления папки**, иначе
фильтры kill-switch останутся и машина будет без интернета (спасение — `MihomoService.exe killswitch remove`
от администратора из любой копии службы).

## Как это устроено

```
C:\Program Files\MihomoService\
├── MihomoService.exe   служба-обёртка (.NET 10, NativeAOT, ~7 МБ)
├── mihomo.exe          ядро
├── config.yaml         ваш конфиг: прокси (+ необязательные переопределения)
├── data\               рабочий каталог ядра: runtime.yaml, cache.db, geo-базы
└── logs\               service.log (обёртка, при старте — её версия), mihomo.log (ядро), ротация по 5 МБ
```

`MihomoService.exe`:

1. ждёт сеть: служба стартует автоматически при загрузке (зависит от `Tcpip`, `Nsi` и `BFE`, они есть
   в любой Windows), а перед запуском ядра ждёт маршрут по умолчанию (`0.0.0.0/0` или `::/0`) через поднятый
   адаптер с рабочим адресом — Ethernet, Wi-Fi, PPPoE, модем; Wintun-адаптеры, включая собственный TUN,
   не в счёт. Если за 2 минуты сеть не появилась, ядро запускается всё равно и подхватит её позже.
   Состояние сети показывает `MihomoService.exe check`;
2. читает `config.yaml`, собирает из `proxies` (и `proxy-providers`) fallback-группу `PROXY` в порядке
   объявления, принудительно включает TUN (`auto-route`, `auto-detect-interface`), DNS-модуль и `mode: rule`,
   при отсутствии подставляет правила (локальные сети → DIRECT, остальное → PROXY) и DNS (fake-ip, DoH
   через туннель — `respect-rules: true`). Якоря YAML (`&`, `*`, `<<:`) в `runtime.yaml` раскрываются;
3. проверяет результат через `mihomo -t` и только после этого записывает `data\runtime.yaml`
   (отклонённый конфиг перепроверяется раз в 2 минуты и при каждом изменении файла);
4. запускает `mihomo.exe -d data -f data\runtime.yaml` внутри job-объекта: если служба упадёт, ядро
   будет завершено вместе с ней;
5. перезапускает ядро при падении (пауза 2 с → 1 мин). Правка `config.yaml`, которую ещё не проверили,
   проверяется перед перезапуском; если её нет или она отклонена — ядро стартует с последним проверенным
   `runtime.yaml`;
6. следит за `config.yaml`: изменения применяются на лету, а если новая версия не прошла проверку,
   ядро продолжает работать на прежней, ошибка пишется в `logs\service.log`.

Служба `MihomoService` работает от LocalSystem; при сбое SCM перезапускает её через 5/10/30 с (при фатальной
ошибке служба завершает свой процесс — для SCM это сбой). Устройство кода — в [CODEMAP.md](CODEMAP.md).

## config.yaml

Обычный конфиг mihomo, лежит рядом с `MihomoService.exe`. Достаточно `proxies` — порядок важен: первый
основной, остальные резервные:

```yaml
proxies:
  - name: main
    type: vless
    server: main.example.com
    port: 443
    uuid: <uuid>
    network: tcp
    tls: true
    udp: true
    flow: xtls-rprx-vision
    servername: www.example.com
    reality-opts:
      public-key: <публичный ключ сервера>
      short-id: <short-id>
    client-fingerprint: chrome

  - name: backup
    type: ss
    server: backup.example.com
    port: 8388
    cipher: 2022-blake3-aes-128-gcm
    password: <ключ сервера>
    udp: true
```

- Прокси socks5/ss/vmess/vless/trojan передают UDP (QUIC, звонки, игры) только с `udp: true` — ставьте его,
  если сервер UDP поддерживает. Без него при kill-switch UDP через этот прокси блокируется.
- Подписки `proxy-providers` тоже входят в fallback-группу — после `proxies`.
- Любые другие ключи mihomo (`rules`, `dns`, `tun.stack`, …) переопределяют значения по умолчанию. Всегда
  принудительно: `tun.enable`, `tun.auto-route`, `tun.auto-detect-interface`, `dns.enable` и `mode: rule`.
  IPv6 по умолчанию выключен (`ipv6: false`). Без своих `rules` локальные сети идут напрямую (при
  `allow-lan: false` — в `REJECT`), остальное — в `PROXY`.

Необязательный раздел `service:` читает только обёртка, ядру он не передаётся:

```yaml
service:
  group-name: PROXY                              # имя fallback-группы
  test-url: https://www.gstatic.com/generate_204 # URL проверки доступности
  interval: 300                                  # период проверки, с
  timeout: 5000                                  # таймаут проверки, мс
  kill-switch: true                              # без туннеля интернета нет (см. ниже)
  allow-lan: true                                # при kill-switch пропускать локальные сети
```

Здесь показаны значения по умолчанию.

## Kill-switch

Включён по умолчанию (`service.kill-switch: true`): без туннеля интернета на машине нет. Служба ставит
постоянные фильтры Windows Filtering Platform, поэтому блокировка действует с ранней загрузки Windows,
при остановленной или упавшей службе и до старта ядра. Разрешено только:

- `mihomo.exe` — соединения с прокси-серверами и его собственный DNS;
- трафик через туннель (адреса TUN, по умолчанию `198.18.0.1/30` — служба задаёт его явно);
- loopback, DHCP, link-local, multicast и broadcast — чтобы адаптер получил адрес;
- локальные сети, если `service.allow-lan: true` (по умолчанию); DNS-запросы (порт 53) мимо туннеля
  запрещены всем, кроме ядра, даже в локальную сеть. При `allow-lan: false` правила по умолчанию
  отправляют частные сети в `REJECT`, а не в `DIRECT`: иначе адреса вне своей подсети (другие VLAN, 10/8)
  уходили бы в туннель и ядро соединялось бы с ними само.

Если `config.yaml` отсутствует или битый, kill-switch всё равно включается. Трафик, который ядро
само отправляет напрямую (`DIRECT` в правилах или в группе), kill-switch не блокирует: это решение
маршрутизации — в том числе собственные правила `DIRECT` для частных сетей при `allow-lan: false`.
`check` предупреждает, если главная группа содержит `DIRECT`.

Включить или выключить можно двумя равноценными способами — оба меняют одно и то же значение
`service.kill-switch` в `config.yaml`, и работающая служба применяет его сразу; ядро при этом коротко
перезапускается (kill-switch меняет и его последнее правило — `MATCH,REJECT`):

- вручную отредактировать `config.yaml`;
- скриптом (сам запросит права администратора), он запишет значение в конфиг и сразу применит его:

```bash
killswitch.cmd off
```

```bash
killswitch.cmd on
```

Без аргумента `killswitch.cmd` показывает состояние. Все команды `killswitch` требуют прав администратора.
Сначала записывается конфиг, потом фильтры: если фильтры применить не удалось, служба приведёт их в
соответствие с конфигом сама.

`install-service.cmd` всегда включает kill-switch: после установки машина защищена. `uninstall-service.cmd`
снимает фильтры, не трогая `config.yaml` (`killswitch remove`), поэтому повторная установка снова защищена.

## Права на папку службы

Служба работает от LocalSystem, поэтому `install-service` закрывает папку: открыть её могут только SYSTEM и
администраторы (владелец — Администраторы). Иначе любой пользователь мог бы подменить `mihomo.exe` и выполнить
код от SYSTEM или выключить kill-switch (папка в корне `C:\` по умолчанию открыта на запись всем), прочитать
учётные данные прокси (`config.yaml`, `data\runtime.yaml`) или адреса, куда ходят другие пользователи
(`logs\mihomo.log`). Права задаются папке и наследуются всем, что в ней появится позже. Если в папке есть
junction или символическая ссылка, установка откажется — через неё права и записи службы ушли бы в другое
место. Для рабочей копии, в которую сборка пишет без повышения прав (`dist\MihomoService`), есть
`install-service.cmd -KeepPermissions` — права остаются как были.

Перед установкой скрипт прогоняет `MihomoService.exe check`; после неё `check` и остальные команды — только от
администратора.

## Обновление

На установленной машине — `update.cmd` из папки службы (права администратора запросит сам):

```bash
update.cmd -WhatIf
```

Скрипт сравнивает установленные версии с последними стабильными релизами: службы — из
`github.com/virtuezo/mihomo-service`, ядра — из `github.com/MetaCubeX/mihomo` (сборка `amd64-v3`, другая —
`-CoreBuild amd64-compatible` и т.п.). `-WhatIf` только показывает, что обновится; без него скрипт спрашивает
подтверждение (`-Yes` — не спрашивать). Скачивание идёт через туннель, поэтому служба должна работать;
каждый архив сверяется с SHA-256, который публикует GitHub. Дальше: заменяемые файлы копируются в `backup\`,
служба останавливается (kill-switch держит сеть закрытой несколько секунд), файлы заменяются, `check`
проверяет `config.yaml` с новыми версиями, служба запускается. Если проверка не прошла или ядро не поднялось,
возвращаются прежние файлы. Заменяются только файлы, которые отличаются от скачанных; если отличий нет
(например, `-Force` на последних версиях), служба не перезапускается. `config.yaml`, `data\` и `logs\` не
трогаются; `-SkipService`/`-SkipCore` — обновить что-то одно.

## Диагностика и регион

`diag.cmd` собирает отчёт в `logs\diag-<время>\`: маршруты (через какой интерфейс уходит трафик к интернету
и к прокси-серверам), DNS, системные прокси, внешний IP, который видят приложения (по TCP и по UDP), состояние
kill-switch и логи. Копии конфигов маскирует `MihomoService.exe`: он разбирает YAML, поэтому скрыты секреты в
любой записи (в одну строку, многострочные, в шаблонах `<<:`), у прокси видны только тип, адрес, порт и
подобное, у URL — только схема и адрес. Ничего не меняет.

Приложения, недоступные в некоторых странах, проверяют не только IP, но и регион Windows и часовой пояс.
`set-region.cmd` выставляет регион всем существующим и новым пользователям и часовой пояс машины
(по умолчанию Нидерланды, Амстердам), запрещает передачу часового пояса клиента в сеансы RDP.
Язык интерфейса не меняется; вошедшим пользователям нужно перезайти.

```bash
set-region.cmd -WhatIf
```

```bash
set-region.cmd -Country RU -TimeZone "Russian Standard Time" -AllowRdpTimeZoneRedirection
```

Первая команда показывает изменения без применения, вторая возвращает Россию.

## Сборка из исходников

Нужны .NET 10 SDK и Visual Studio (или Build Tools) с компонентом «C++ x64/x86 build tools» (для NativeAOT).
Ядро положите в `bin\` (`mihomo-windows-amd64*.exe` из [релизов mihomo](https://github.com/MetaCubeX/mihomo/releases);
сборка `-v3` требует процессор с AVX2, для старых CPU берите `mihomo-windows-amd64-compatible`).

```bash
scripts\build.cmd
```

Результат — `dist\MihomoService\`: `MihomoService.exe`, `mihomo.exe`, скрипты службы, `LICENSE` и лицензии
сторонних компонентов. Параметры: `-Core <путь к mihomo.exe>`, `-Config <путь к config.yaml>`. Если служба запущена из
`dist\MihomoService`, сборка откажется перезаписывать файлы — сначала остановите её.

У каждого `scripts\*.ps1` есть обёртка `*.cmd`: она обходит ExecutionPolicy, передаёт аргументы дальше,
при необходимости сама запрашивает права администратора (UAC) и не закрывает окно при запуске двойным кликом.

Запустить в консоли для отладки (от администратора, Ctrl+C — остановка):

```bash
dist\MihomoService\MihomoService.exe
```

Тесты:

```bash
dotnet test MihomoService.slnx
```

Если в `dist\MihomoService` лежит свой `config.yaml`, помните: в нём учётные данные прокси — следите, куда
копируете папку.

## Выпуск релиза

```bash
scripts\release.cmd
```

Версия — `<Version>` в `src\MihomoService\MihomoService.csproj` (перед выпуском поднимите её), тег —
`v<Version>`. Скрипт требует чистое рабочее дерево и отправленный на GitHub коммит, собирает `dist`
(`build.ps1`), упаковывает `MihomoService-v<Version>.zip` (без `config.yaml` и логов) и после подтверждения
публикует релиз через `gh`. Ядро в релиз попадает из `bin\` — обновите его там заранее.
